# v1.7.0

## Added
- `loki infra`: local-machine infrastructure chaos — kill, suspend/resume, CPU stress, and memory stress on processes, plus optional local Docker container kill/pause. Targets are selected by `--pid`, `--port` (listening only), or `--name`.
- `loki infra cleanup`: reconciles and kills orphaned stress workers left behind if a `loki infra cpu-stress`/`memory-stress` run itself gets killed from the outside, using a tracking file written before the stress workers sleep.
- `CHANGELOG/` folder with one markdown file per release; the release workflow now publishes exactly that file's content as the GitHub Release body instead of auto-generated notes.

## Fixed
Five real bugs found via adversarial testing of `loki infra`:
- `cpu_stress(workers=0)` was silently replaced by the CPU-count default (falsy check instead of `is not None`).
- The protected-process list used substring matching, blocking legitimate targets like `initdb.exe`; it's now an exact-name match.
- `find_processes(port=N)` matched any connection using that port, not just the process actually listening on it.
- `memory_stress` reported `success=True` even when the spawned worker crashed instantly on a negative/absurd `--mb`.
- Stress workers survived a hard kill of the parent `loki infra` process, burning CPU/memory indefinitely; they're now tracked and recoverable via `loki infra cleanup`.
